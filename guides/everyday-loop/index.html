Everyday loop ​

A one-page cheat sheet. Same commands every day.

First time here?

Do the 10-minute tutorial once first. It includes a paste-ready example.

First time ​

bash
sdd setup
sdd go "What you want to build"
sdd go --answer "The answer to the question it printed"

On a terminal, sdd setup walks folder, workflow, host, roles, model, a check, and an optional first change. Press Enter to create planner, architect, and builder when the folder has no role files. Set up one missing piece later with sdd setup --step model. The planner plans, the architect names the modules, and the builder builds the change pack. Pass -w to map those duties onto another workflow. sdd go asks, drafts, and hands the next stage to the next role. What they are, why that helps, and the setup commands are in Roles and duties. Give a role extra context with sdd role context <name> --text "...".

Tiny fix ​

bash
sdd doctor
sdd new "Short title of the work" -w hotfix -y
sdd status
# edit the intent file sdd printed
sdd next
sdd next
sdd complete

sdd verify only says PASS when commands actually ran and all exited 0. With no verify.commands configured (the default commands: []) it says NOT RUN and exits 1 — that is not a failure of your code, it means nothing was checked automatically. Complete the checklist in local-test-results.md by hand, or add commands to the stage in .sdd/workflows/<workflow>.yaml. Only verify commands marked required: true block sdd complete. A required note, and a hard gate, also block it.

Without -w, most titles open feature. That path is not this two-step sdd next. Use Simple feature. On feature, fill local-test-plan.md and local-test-results.md before sdd complete.

From a product backlog after greenfield:

bash
sdd backlog list
sdd backlog start F-001
# opens feature by default — fill both test files, then sdd complete

(sdd new "…" is for free-form titles; sdd backlog start is only for F-001 rows in memory/features.md.)

New product (once) ​

bash
sdd greenfield "One sentence product idea"
# fill vision → sdd next → requirements → features → architecture
sdd complete
sdd backlog list
sdd backlog start F-001

Several things at once ​

bash
sdd status --list             # see open work
sdd checkout <change-id>      # switch which one is active

Escape hatches ​

bash
sdd skip design -r "not needed for this small change"
sdd use feature -r "this grew bigger than a hotfix"
sdd next --force              # rare: skip checks (use carefully)
sdd next --no-agent           # move stages without launching AI

Name a team (optional) ​

The loops above do not need this. Use it when more than one role works in the repo.

bash
sdd team init --template software
sdd team show
sdd role edit developer --stages implement
sdd role context developer --text "This app uses pnpm."
sdd new "Ship the export" -w team-software -y
sdd team signoff --note "I accept this stage"
sdd role room
sdd role room post "The list stays empty when the query is blank."

team-software is requirements, clarifications, high-level design, low-level design, plan, test plan, development, pull-request review, QA testing, QA sign-off, product-owner review, and product-owner sign-off. Each stage waits for sdd team signoff on that commit. A role prepares the page and does not sign. Who prepares each stage, and how to assign those stages, are in Roles and duties.

sdd role room prints the active change. sdd role room <change-id> prints that change. sdd role room --stage <stage> and sdd role room --stage=<stage> print that stage. On post, --change and --stage select the file.

A run named as a bot can read a file, search, run one allowlisted check, write a file, and commit on its own branch. The check result is changes/<id>/evidence/<sha>.json. Push and merge stay with a person.
