# Acceptance

> **Issue #36: show missing bundled workflows and adopt matching files** · `2026-10-23-issue-36-show-missing-bundled-workflows`

- A project with only `patch.yaml` and no `.sdd/.generated.json` makes `sdd workflows` print `patch` and `Not copied yet:` including `feature`, plus `sdd init --here --force`.
- `sdd new "probe" -w feature -y --no-agent` exits non-zero. The message contains `Workflow "feature" is not available. Available: patch` and `This CLI ships feature. Run sdd init --here --force to copy new defaults.`
- `sdd init --here --force --no-agent` creates `feature.yaml`, leaves a matching `patch.yaml` byte-identical, and stores a hash for `patch.yaml`. It does not report that file as `not generated by sdd`.
- After that, `sdd new "probe" -w feature -y --no-agent` exits 0.
- An unmarked `patch.yaml` that differs from the bundle stays byte-identical, is reported as not generated, and receives no hash.
- A matching unmarked file, once recorded, is refreshed on a later `--force` when the bundled bytes change. An unmarked file that differs is not refreshed.
